# Product Engineering

## Purpose

Bridge product intent and implementation by defining the smallest valuable
scope, clear stories, and a phased plan that manages risk.

## When to use

- Turning a fuzzy product goal into buildable work.
- Deciding what is in/out of an MVP or release.
- Prioritizing a backlog or sequencing delivery.

## Workflow

1. Clarify the user, the problem, and the outcome that defines success.
2. Define the MVP: the smallest slice that validates value.
3. Write user stories with acceptance criteria (testable, user-centric).
4. Prioritize by value vs effort vs risk; cut or defer the rest.
5. Sequence delivery into phases that each ship something usable.
6. Surface usability and risk concerns early, not after build.

## Anti-patterns

- Building everything at once instead of a validated slice.
- Stories written as technical tasks with no user value or acceptance criteria.
- Prioritizing by loudest request rather than value/effort/risk.
- Ignoring usability until the feature is "done".

## Output

- An MVP definition, prioritized stories with acceptance criteria, and a phased plan.
