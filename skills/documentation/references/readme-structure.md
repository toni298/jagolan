# README structure

A README should get a reader from zero to running quickly, then explain enough
to use and contribute.

Recommended order:

1. **One-line description** — what it is and who it's for.
2. **Quick start** — install + run in the fewest possible steps, copy-pasteable.
3. **Usage** — the most common tasks with short examples.
4. **Configuration** — environment variables and options, with defaults.
5. **Architecture (brief)** — only the mental model a contributor needs.
6. **Development** — how to test, lint, and build locally.
7. **Troubleshooting / FAQ** — common errors and fixes.
8. **License / contributing** — links, not full text.

Principles:

- Put the "how do I run this" answer above the fold.
- Every command should be copy-pasteable and actually work from a clean clone.
- Prefer one good example over exhaustive option tables.
- Keep internals out of the README; link to deeper docs/ADRs instead.
